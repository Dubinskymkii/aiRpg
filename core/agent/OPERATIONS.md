# Agent Operations

Этот файл описывает операции репозитория в терминах результата. Это источник правды для агента.

PowerShell-файлы в `tools/` являются необязательными helper-скриптами. Агент НЕ должен читать их для понимания операции. Если среда не умеет запускать PowerShell, агент выполняет тот же контракт напрямую через доступные файловые или repository-инструменты.

## Общие правила

1. Сначала определить операцию по намерению пользователя.
2. Прочитать только источники, нужные этой операции.
3. Выполнить обязательный результат независимо от runtime.
4. Не считать операцию выполненной только потому, что helper существует или был вызван.
5. После мутаций канона выполнить `VALIDATE_CAMPAIGN`, если ниже не указано иное.
6. `ACTIVE.md` является навигационной закладкой, а не долговременным каноном.
7. Все пути ниже считаются относительно корня репозитория.

## CREATE_CAMPAIGN

Когда:
- пользователь создаёт новую кампанию: `*new <campaign_id> [| название]`.

Вход:
- `campaign_id`: только латиница, цифры, `_`, `-`;
- отображаемое название может быть любым.

Обязательный результат:
- создать `campaigns/<campaign_id>/CAMPAIGN.md`;
- создать:
  - `world/artifacts/`
  - `world/characters/main/`
  - `world/characters/secondary/`
  - `world/characters/tertiary/`
  - `world/factions/`
  - `world/history/`
  - `world/places/`
  - `world/sessions/`
  - `assets/maps/`
  - `assets/portraits/`
  - `saves/`;
- создать:
  - `world/history/recent.md`
  - `world/history/middle.md`
  - `world/history/mythology.md`
  - `world/history/timeline.md`
  - `world/places/MAP.md`
  - `world/sessions/ACTIVE.md`;
- записать `campaign_id` в `.airpg/ACTIVE_CAMPAIGN`;
- `ACTIVE.md` должен содержать базовые ссылки:
  - `core/rules/RULES.md`
  - `core/rules/PERCEPTION.md`
  - `core/world/COMPACTION.md`
  - собственный `ACTIVE.md`;
- после создания НЕ начинать сцену;
- попросить описание первого игрового персонажа.

Допустимый helper:
- `tools/campaign.ps1 start <campaign_id> [title]`.

После:
- кампания создана, но игра ещё не готова;
- следующая операция: `CREATE_PLAYER_CHARACTER`.

## CREATE_PLAYER_CHARACTER

Когда:
- новая кампания создана и пользователь дал описание игрового персонажа;
- или к уже идущей кампании присоединяется новый игрок.

Прочитать:
- `core/rules/RULES.md`;
- `core/world/characters/KNOWLEDGE.md`;
- шаблоны из `core/world/templates/character/`;
- активный `ACTIVE.md`.

Определить по описанию пользователя:
- имя или рабочее обращение игрового персонажа;
- роль;
- 6 характеристик;
- 2-3 сильные стороны;
- 1-2 слабости;
- стиль речи;
- небольшой фрагмент прошлого;
- начальные цели;
- стартовый инвентарь;
- стартовые отношения, если они уже установлены пользователем;
- стартовую игровую зацепку.

Не оптимизировать героя под механику. Характеристики должны следовать описанию пользователя.

Обязательный результат:
создать `campaigns/<campaign_id>/world/characters/main/<character_id>/` с файлами:
- `profile.md`
- `stats.md`
- `speech_style.md`
- `current_goals.md`
- `long_term_goals.md`
- `inventory.md`
- `relationships.md`
- `short_memory.md`
- `long_memory.md`

Если факт неизвестен, писать `Пока не установлено`, а не выдумывать.

Затем обновить `ACTIVE.md`:
- добавить игрового персонажа в `Who is nearby`, если он присутствует в текущей сцене;
- заполнить текущую сцену, позицию, ближайшую цель и угрозу;
- в `Read before continuing` обязательно добавить:
  - игрового персонажа `profile.md`;
  - игрового персонажа `stats.md`;
  - игрового персонажа `speech_style.md`;
  - игрового персонажа `inventory.md`;
- дополнительные файлы героя добавлять только если они нужны для следующего кадра.

После:
- выполнить `VALIDATE_CAMPAIGN`;
- только после успешной валидации разрешён первый игровой кадр.

Допустимый helper для создания каркаса:
- `tools/promote-character.ps1 <campaign_id> <character_id> main [display_name] [role]`.
Helper создаёт только структуру. Агент всё равно обязан заполнить её каноном и обновить `ACTIVE.md`.

## PROMOTE_CHARACTER

Когда:
NPC становится значимым:
- получил имя и повторяется;
- имеет устойчивую роль;
- влияет на сюжет;
- управляет людьми или ресурсами;
- имеет собственные цели;
- стал союзником, врагом, посредником или важным свидетелем.

Категории:
- `secondary`: повторяющийся значимый NPC;
- `tertiary`: именованный бытовой NPC без собственной большой дуги.

Обязательный результат:
создать полную папку персонажа с теми же 9 файлами, что у главного героя.

Перенести только уже установленный канон. Не заполнять неизвестные детали догадками.

Если NPC присутствует в текущей сцене:
- добавить его в `Who is nearby`;
- добавить в `Read before continuing` минимум:
  - `profile.md`;
  - `speech_style.md`;
- добавлять `stats.md`, goals, relationships и memory, если они нужны следующему кадру.

После:
- `VALIDATE_CAMPAIGN`.

## CREATE_PLACE

Когда:
место впервые стало содержательно значимым:
- получило имя;
- игрок вошёл туда;
- там произошла важная сцена;
- оно влияет на расстояние, риск или маршрут;
- к нему планируют возвращаться.

Перед созданием:
- проверить `world/places/MAP.md`;
- проверить существующие папки мест;
- не создавать второй объект, если подходящее место уже существует.

Обязательный результат:
`world/places/<place_id>/`:
- `profile.md`
- `geography.md`
- `state.md`
- `history.md`
- `events/`

И запись в `MAP.md`:
`- <place_id> | <display_name> | type: <type> | coords: preliminary`

Если точная география неизвестна, использовать `preliminary`.

После:
- добавить место или его профиль в `Read before continuing`, если оно важно следующему кадру;
- `VALIDATE_CAMPAIGN`.

## UPDATE_ACTIVE_CONTEXT

Когда:
- меняется сцена;
- меняется состав присутствующих;
- меняется текущая позиция;
- появляется новый значимый источник, нужный следующему кадру;
- выполнена компактизация.

`ACTIVE.md` должен оставаться короткой навигационной закладкой.

Он хранит:
- Current scene;
- Where the group is;
- Who is nearby;
- Immediate goal;
- Immediate threat;
- Read before continuing;
- Active events;
- Uncompacted changes;
- GM working notes.

Правила `Read before continuing`:
- всегда:
  - `core/rules/RULES.md`
  - `core/rules/PERCEPTION.md`
  - `core/world/COMPACTION.md`
  - текущий `ACTIVE.md`;
- для каждого игрового персонажа, присутствующего в текущей сцене:
  - `profile.md`
  - `stats.md`
  - `speech_style.md`
  - `inventory.md`;
- для значимого NPC, способного говорить или действовать в следующем кадре:
  - минимум `profile.md`
  - `speech_style.md`;
- место, фракцию, событие, goals, relationships или memory подключать только если они реально нужны следующему кадру.

Не использовать `ACTIVE.md` как замену этим источникам.

## VALIDATE_CAMPAIGN

Когда:
- после операций, меняющих канон;
- после обязательной компактизации;
- перед save;
- перед первым игровым кадром новой кампании.

Проверить минимум:

Структура:
- все обязательные каталоги мира существуют;
- `places/MAP.md` существует;
- `sessions/ACTIVE.md` существует.

Персонажи:
- у каждого значимого персонажа существуют все 9 обязательных файлов;
- у каждого игрового персонажа в `main/` есть непустой `inventory.md`.

Места:
- у каждой папки места есть:
  - `profile.md`
  - `geography.md`
  - `state.md`
  - `history.md`
  - `events/`;
- каждое место присутствует в `MAP.md`.

ACTIVE:
- не более 150 строк;
- каждая указанная ссылка существует;
- для каждого игрового персонажа из `main/`, указанного в `Who is nearby`, в `Read before continuing` есть:
  - profile
  - stats
  - speech_style
  - inventory;
- для каждого значимого secondary/tertiary NPC, указанного в `Who is nearby`, есть минимум:
  - profile
  - speech_style.

Если проверка не пройдена:
- не создавать save;
- не продолжать первый кадр после создания кампании;
- не продолжать следующий кадр после обязательной компактизации.

Допустимый helper:
- `tools/validate-campaign.ps1 -CampaignId <campaign_id>`.

## COMPACT_CAMPAIGN

Когда:
- сон;
- длительный отдых;
- конец сцены или сессии;
- длинный переход;
- скачок времени;
- устойчивая потеря сознания;
- явная команда пользователя.

Источник:
- `core/world/COMPACTION.md`.

Обязательный результат:
- повысить ставших значимыми NPC;
- создать ставшие значимыми места;
- обновить память, отношения, цели и инвентарь;
- обновить места, события, фракции, историю;
- очистить `ACTIVE.md` от устойчивого канона;
- обновить `Read before continuing` под следующий кадр.

После:
- `VALIDATE_CAMPAIGN`.

---

## SAVE_CAMPAIGN

Перед:
- успешный `VALIDATE_CAMPAIGN`;
- канон уже скомпакчен.

Обязательный результат:
- `saves/<save_id>/world/` содержит snapshot текущего `world/`;
- `saves/<save_id>/SAVE.md` содержит campaign id, save id и время создания.

Допустимый helper:
- `tools/campaign.ps1 save <campaign_id> <save_id>`.

---

## RESTORE_CAMPAIGN

Когда:
- пользователь явно просит восстановить save.

Обязательный результат:
- заменить текущий `world/` содержимым `saves/<save_id>/world/`;
- не изменять save;
- после восстановления выполнить `VALIDATE_CAMPAIGN`;
- обновить `.airpg/ACTIVE_CAMPAIGN`, если восстановленная кампания должна стать активной.

Восстановление разрушительно для текущего `world/`, поэтому выполнять только по явной команде пользователя.

---

## ACTIVATE_CAMPAIGN

Когда:
- пользователь выбирает существующую кампанию.

Обязательный результат:
- проверить, что `campaigns/<campaign_id>/` существует;
- записать id в `.airpg/ACTIVE_CAMPAIGN`;
- прочитать `world/sessions/ACTIVE.md`;
- затем прочитать источники из `Read before continuing`.

Не начинать игру, если ACTIVE отсутствует или его обязательные ссылки сломаны.
